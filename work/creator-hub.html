Creator Hub

A production-shaped Rails API for connecting multiple social media accounts and publishing to all of them through one interface — an adapter pattern hiding four very different platform APIs behind one shape.

Real API responses ↓

Why no screenshots

It's an API — there's no UI

The examples below are real responses from the running app (JWT-authenticated, hitting an actual local instance), with account-identifying details replaced by placeholders before publishing anything here.

How it works

One adapter interface, four platforms

Every platform — YouTube, Instagram, Twitter/X, LinkedIn — implements the same adapter interface (connect, publish, fetch stats). The rest of the app never branches on which platform it's talking to.

Engineering highlights

What was actually hard here

One dead platform shouldn't fail the whole response

Each platform's stats fetch is rescued independently and reported as a per-item error field rather than the whole request 500ing because one of four platforms is unreachable.

A syntax bug that had been a hard 500 for a while

cp.stats_synced_at&.> 30.minutes.ago looks like it should work, but Ruby can't parse an operator method call through &. without explicit parentheses. Found while exercising this project for this portfolio — the analytics endpoint was a guaranteed 500 for every request. Fixed to a plain && check.

JWT auth returned via header, not body

Sign-in returns the JWT in the Authorization response header (devise-jwt's default), not the JSON body — every client integration has to know to read it from there.
